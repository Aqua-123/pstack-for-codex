### Autopilot-full

**You own the verdicts, never the PRs. One owner runs each PR from build to merge, and nothing merges without your clean swarm verdict.** For "autopilot this queue", "full autopilot", and one-owner-per-PR programs. The job is a queue of independent PRs handed over to drive to merged with full autonomy. Orchestrate runs a standing program whose coordinator lands verified work itself and whose workers never merge; here each PR's owner carries the whole lifecycle through the merge, and the root keeps only verification, countersigns, and audits.

1. **Mark the operator's items and honor state-then-wait.** Items the operator names remain theirs to review and merge. A request to state a plan stops after delivering that plan. Execute only within the operator's existing authorization. Goals and hourly thread heartbeats require explicit lifecycle authority under the runtime contract.
2. **Spawn one owner per PR with an early trail.** Resolve the forge once. Use a supported built-in PR tool for its available operations, otherwise `gh` or `origin pr` when its CLI resolves the repository. Record fallback to `gh`. Give each owner an isolated worktree and bounded brief. The parent retains external writes unless the user explicitly assigns them elsewhere. Owners build, self-prove, triage Bugbot skeptically, run `$deslop` and `$no-comments`, and return publishable artifacts. Keep `decisions.tsv` and a `children.tsv` with each child's ID, expected runtime, and state. Set expected runtime no lower than the longest comparable observed run. Publish authorized branch snapshots after verifiable units. Rebase before the code-ready report and babysit. In fix rounds, preserve that merge base. Rebase again only at merge prep, on a `git merge-tree` conflict with trunk, or on CI failure caused by trunk. Run repository pre-review checks on the committed head before each review-facing push. A hook pass is not proof. Report the code-ready SHA after cleanup, every later patch-changing push SHA, and merge-ready SHA after self-proof, CI, and babysit finish. Self-proof, CI, and babysit can overlap the swarm after code-ready.
3. **Run owners in true parallel and never stack.** Many owners at once when PRs are self-contained: one writer per branch, disjoint files, cross-PR drift absorbed by rebase. Only genuinely overlapping work serializes. Self-contained PRs branch straight off main, and sequenced work is merge-then-branch. Independent PRs use the resolved forge without requiring Graphite. One exception: an owner that must split a genuinely dependent change may hold a short private stack.
4. **Swarm-verify every round before merge.** Each code-ready head and later patch-changing push starts a round. Run independent gates, live behavior, and at least two review lanes with the full brief and distinct focuses, per the **swarm** skill. Compare the load-bearing scenario with current trunk. If trunk lacks the feature, record that fact and prove the added behavior and user-visible end state. Audit merge-ready receipts before the verdict. Missing live proof fails closed. Batch every proven finding into one fix-forward, including defects filed as notes. Behavior findings require a red test covering every site with the same defect, or a repro receipt where tests cannot show it. Add the defect to the next round's brief. The next head gets a fresh verdict except for lanes reusable under `playbooks/shipping.md`. The root's clean verdict must match the merge-ready patch.
5. **On a clean verdict, merge within authority and start a fresh owner.** Merge prep follows the start of the round's lanes and ends with a rebase onto current trunk. Report the new SHA and require CI on that head. Apply the patch-id rule before retaining the verdict. A later trunk move alone does not require a rebase. Immediately before merge, fetch trunk, require a clean `git merge-tree`, and check trunk changes since the merge base against both PR paths and paths that select CI. Overlap or conflict requires another rebase, new SHA, fresh CI, and repeated checks. The parent performs the authorized merge unless explicitly assigned elsewhere. The completed owner returns; a fresh owner takes the next independent item. Operator-named items wait for the operator's merge.
6. **Run the root layer.** A newly raised pinned gate needs a fresh evidenced countersign within the user's approval authority. Never bypass forge approval enforcement. Landed values absorbed from trunk are drift. With authorized lifecycle scope, run an hourly thread heartbeat. Every tick re-reads this playbook from trunk and the live goal, audits progress by commits, pushes, check deltas, and artifacts, and appends the queue table to the decision log. Message only previously unreported tracked changes such as a PR opened, code-ready head, round, verdict, merge, stuck lane and action, blocker added or cleared, or operator decision. Check supported live status and each owner's `children.tsv`. On error or runtime exceeded without an artifact, stand the lane down, reconcile partial writes, record it stuck, and allow at most one bounded replacement. A repeated stall yields a visible gap or blocker. Cancellation is not proof writes stopped. Keep the audit active until delegated work is reconciled, including after the final merge. Run post-merge bot-comment and retrospective passes when merges batch.
7. **Stand down instantly on the operator's stop.** Her hold or stand-down reaches every owner as a zero-writes order immediately. Owners hold their briefs until she releases them.

**Reply:** the queue, owners, states, head SHAs, verifier verdicts, merges, fresh owners, countersigns and authority, operator gates, and decision trails.
